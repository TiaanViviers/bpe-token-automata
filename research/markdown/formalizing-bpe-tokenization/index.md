# Formalizing BPE Tokenization

Martin Berglund Department of Computing Science Umeå University Umeå, Sweden mbe@cs.umu.se

Brink van der Merwe Department of Computer Science Stellenbosch University Stellenbosch, South Africa abvdm@cs.sun.ac.za

In this paper, we formalize practical byte pair encoding tokenization as it is used in large language models and other NLP systems, in particular we formally define and investigate the semantics of the SentencePiece and HuggingFace tokenizers, in particular how they relate to each other, depending on how the tokenization rules are constructed. Beyond this we consider how tokenization can be performed in an incremental fashion, as well as doing it left-to-right using an amount of memory constant in the length of the string, enabling e.g. using a finite state string-to-string transducer.

## 1 Introduction

Many modern NLP systems, for example large language models such as the GPT models which underpin services like ChatGPT [\[6\]](#page-11-1), operate on a *tokenization* of text. This tokenization defines an alphabet of symbols (in the formal languages sense) which include as many common words and fragments of words as possible. For example, the OpenAI GPT-2 model has an alphabet size (a "vocabulary" in their terminology) of 50,257 tokens, which is enough to turn the sentence "taking a ride on a boat" into[<sup>1</sup>](#page-0-0) the token sequence " taking a ride on a boat ", as all words are common enough to be in the alphabet, but "partaking in a nautical excursion aboard a vessel" is tokenized as " part aking in a n autical exc ursion ab oard a ves sel ", as the words are uncommon, but fragments of the words are common enough. This alphabet is then more semantically rich. For example, forming unusual plurals (turning " earths " into " earth s "), or making a noun into a "non-existing" verb (i.e. turning " verb " into " verb ing "), retaining the informative root word, but also it generally makes the model more robust to misspellings and other minor transformations of the text [\[7\]](#page-11-2).

One common way of performing this tokenization is by byte pair encoding [\[7\]](#page-11-2) (BPE), used by OpenAI GPT models, and e.g. the recent Swedish GPT-SW3 model [\[9\]](#page-11-3), which uses the Google tokenizer implementation SentencePiece [\[4\]](#page-11-4). BPE operates similar to a compression technique, with a dictionary of token merges constructed greedily maximizing the number of tokens that get merged in a training set (see Remark [1](#page-4-0) for a sketch of the procedure).

There are other methods for performing this type of tokenization, e.g. the unigram language model also implemented in SentencePiece [\[4\]](#page-11-4), where tokens are individually weighted. We do not consider this case here. BPE tokenization can be contrasted to lexical analysis [\[5\]](#page-11-5), as lexical analysis (as exhibited in e.g. the POSIX tool lex) differs in that the rules are typically authored by hand, and break the string into an infinite language of tokens divided among a constant set of categories. Consider for example extracting arbitrarily long identifiers and string constants when parsing programming languages. BPE tokenization can also be viewed as one case of text segmentation in natural language processing

<span id="page-0-0"></span><sup>1</sup>We are for the purposes of this example ignoring some details, involving whitespace and the string beginning and end.

(see e.g. [\[3\]](#page-11-6)), which covers e.g. breaking a text into topics, sentences, or words. These text segmentation algorithms have commonly been at least partially supervised or authored, where the tokenization algorithms considered here are designed for language-agnostic unsupervised learning.

The way the tokenization procedure is defined and implemented in common tools [\[2,](#page-11-7) [4\]](#page-11-4) is essentially *global:* the highest priority rule that can be applied to the text is, no matter where in the text this application would happen. This is not *usually* a problem, as the text is *pretokenized* by splitting it on whitespace before applying the main tokenization procedure. That is sufficient to make tokenization algorithm behavior irrelevant in general, however:

- Some natural languages simply do not use interword whitespace, such as writing systems for Thai, Chinese and Japanese.
- In many artificial (e.g. programming) languages whitespace is common but not required, for example "minified" code is very common [\[8\]](#page-11-8), where all unnecessary whitespace is removed to reduce file sizes. Language models are commonly trained at least partially on code, e.g. the GPT-SW3 dataset contains 9.5% code in various programming languages [\[1\]](#page-11-9).
- In some cases there is whitespace, but pretokenizing using it does not produce the best tokens. E.g. in the SQL query language "LEFT OUTER JOIN" is a single concept, and would ideally be a single token.
- Even in cases where the pretokenization normally works well, such as for English, a hypothetical system relying heavily (more so than any currently existing system) on the pretokenization creating short text fragments may then be vulnerable to a denial of service attack. Compare to e.g. [\[10\]](#page-11-10) on such attacks for regular expression matchers.

As such, as these systems find their way into broader and more complex use, it becomes interesting to investigate robust algorithms for operating on tokenizations. We investigate the following questions.

- Can we perform a BPE tokenization online: observing a stream of text can we output a stream of tokens using only limited memory and computation?
- If we have a tokenization of a large text, and the text is modified in a localized way, can we compute a localized update of the tokenization?

The answers to all of these questions are interconnected, but first we need firm definitions of the semantics we are considering.

The outline of this paper is as follows. After introducing our notation, we define (formally) SentencePiece and HuggingFace tokenizers. Then we consider how to do tokenization in a streaming fashion. This is followed by a short section outlining our envisioned future work.

## 2 Notation

An alphabet Σ is a finite set of symbols. Let Σ ∗ denote all strings over the alphabet Σ, including the empty string ε, and Σ <sup>+</sup> = <sup>Σ</sup> <sup>∗</sup>∖{ε}. A sequence of non-empty strings is a *tokenization*, e.g. for *<sup>u</sup>*1,...,*u<sup>n</sup>* ∈ <sup>Σ</sup> + , we denote this *u*<sup>1</sup> ≀⋯≀*<sup>u</sup>n*. By <sup>Σ</sup> ≀ we denote the set of all tokenizations constructed from strings from <sup>Σ</sup> ∗ . We refer to those strings as the *tokens*. Let <sup>π</sup> ∶ <sup>Σ</sup> ≀ → <sup>Σ</sup> ∗ be the concatenation of the strings in a tokenization, e.g. <sup>π</sup>(*<sup>u</sup>*<sup>1</sup> ≀⋯≀*<sup>u</sup>n*) = *<sup>u</sup>*1⋯*<sup>u</sup><sup>n</sup>* ∈ <sup>Σ</sup> ∗ . As a special case, we let <sup>π</sup> applied to the tokenization with *<sup>n</sup>* = 0, be the empty string. When <sup>π</sup>(*<sup>u</sup>*<sup>1</sup> ≀⋯≀*<sup>u</sup>n*) = *<sup>w</sup>* ∈ <sup>Σ</sup> ∗ , we say that *u*<sup>1</sup> ≀⋯≀*<sup>u</sup><sup>n</sup> is a tokenization of w*. For <sup>τ</sup> = *<sup>u</sup>*<sup>1</sup> ≀⋯≀*<sup>u</sup>n*, we denote by ∣τ∣ the integer *<sup>n</sup>*. Thus, ∣τ∣ = 0 if and only if <sup>τ</sup> is the empty tokenization. Also, for *<sup>u</sup>* ∈ <sup>Σ</sup> ∗ , we let ∣*u*∣ denote the length of *<sup>u</sup>*, i.e. the number of symbols from <sup>Σ</sup> in the string *<sup>u</sup>*. It will be clear from the context and notation when <sup>τ</sup> denotes a tokenization with ∣τ∣ = 1, i.e. a tokenization of length one instead of a string of length one, given that in this case, τ could be interpreted as either. In fact, given our notational conventions discussed below, the symbol τ will always represent a tokenization.

In addition to using ∣τ∣ and ∣*u*∣ for the length of a tokenization <sup>τ</sup> and length of a string *<sup>u</sup>* respectively, we use ∣*S*∣ to denote the cardinality of a (finite) set *<sup>S</sup>*.

Differentiating between strings and tokenizations becomes important as we continue, so we adopt some conventions. Let Σ denote the alphabet whenever not otherwise specified. When giving examples, we always use <sup>Σ</sup> = {*a*,*b*,*c*,...}. Furthermore, we always let <sup>α</sup>,β,<sup>γ</sup> be variables denoting symbols from the alphabet, *u*,*v*,*w* denote strings, and τ,φ denote tokenizations, including all sub-/superscripted variants of each. In other words, *<sup>u</sup>*,*v*,*<sup>w</sup>* ∈ <sup>Σ</sup> ∗ and <sup>τ</sup>,φ,<sup>ψ</sup> ∈ <sup>Σ</sup> ≀ , and for that matter *<sup>u</sup>*1,*u*<sup>2</sup> ∈ <sup>Σ</sup> ∗ , τ ′ ∈ Σ ≀ , etc. As such we may write e.g. *<sup>u</sup>*≀<sup>τ</sup> ≀*<sup>v</sup>* = <sup>φ</sup> to mean that <sup>τ</sup> is a tokenization where the first token is *<sup>u</sup>*, the last is *<sup>v</sup>*, and the intervening tokens form the tokenization <sup>τ</sup>, so ∣φ∣ = ∣τ∣+2.

# 3 Tokenizing Semantics

First, we define a byte pair dictionary, which will be used to restrict the set of possible tokenizations for a given string *w*. We will only use *D* and its sub-/superscripted variants to denote a dictionary.

Definition 1. A byte pair *dictionary D* = [*<sup>u</sup>*<sup>1</sup> ≀*<sup>v</sup>*1,...,*u<sup>n</sup>* ≀*<sup>v</sup>n*] of length ∣*D*∣ = *<sup>n</sup>* is a sequence of tokenizations *u*1 ≀*<sup>v</sup>*1,...,*u<sup>n</sup>* ≀*<sup>v</sup>n*, with each tokenization *<sup>u</sup><sup>i</sup>* ≀*<sup>v</sup><sup>i</sup>* being of length 2. We call each *<sup>u</sup><sup>i</sup>* ≀*<sup>v</sup><sup>i</sup>* <sup>a</sup> *rule* and say that (a rule) *u<sup>i</sup>* ≀*<sup>v</sup><sup>i</sup>* has *higher priority* than *<sup>u</sup><sup>j</sup>* ≀*vj* , when *<sup>i</sup>* < *<sup>j</sup>*.

We write <sup>τ</sup> ⇒*<sup>D</sup>* <sup>τ</sup> ′ if <sup>τ</sup> = <sup>φ</sup> ≀*u*≀*v*≀<sup>φ</sup> ′ and τ ′ = <sup>φ</sup> ≀*uv*≀<sup>φ</sup> ′ , for some *<sup>u</sup>*≀*<sup>v</sup>* ∈ *<sup>D</sup>*. The dictionary *<sup>D</sup>* will always be clear from the context, thus we omit the superscript on ⇒. We let ⇒<sup>+</sup> and ⇒<sup>∗</sup> denote the transitive and reflexive transitive closure of ⇒, respectively. Also, for *<sup>w</sup>* = <sup>α</sup>1⋯<sup>α</sup>*n*, we denote by <sup>T</sup> <sup>∅</sup>(*w*) the tokenization α<sup>1</sup> ≀⋯≀<sup>α</sup>*n*.

Next, we transfer terminology used in derivations over context-free grammars, to our setting. For *<sup>w</sup>* = α<sup>1</sup> ...α*n*, we begin a derivation for a tokenization with <sup>T</sup> <sup>∅</sup>(*w*), although a more complicated pretokenizer step could certainly also be of interest, but not considered in this paper. Whereas in the case of contextfree grammars, a derivation step consists of applying a grammar rule by replacing the non-terminal on the left-hand side of a rule, by its right-hand side, in our setting, a derivation step is of the form <sup>φ</sup> ≀*<sup>u</sup><sup>i</sup>* ≀*vi* ≀φ ′ ⇒ <sup>φ</sup> ≀*<sup>u</sup>iv<sup>i</sup>* ≀φ ′ , for *u<sup>i</sup>* ≀*vi* in *D*. A derivation terminates when no further rules from *D* can be applied.

The definition of a base tokenizer on *D*, which ignores the priority of rules in *D*, is as follows.

<span id="page-2-0"></span>Definition 2. For *<sup>D</sup>* = [*<sup>u</sup>*<sup>1</sup> ≀*<sup>v</sup>*1,...,*u<sup>m</sup>* ≀*<sup>v</sup>m*] and *<sup>w</sup>* = <sup>α</sup>1⋯<sup>α</sup>*n*, we obtain the *base tokenizations of w by D,* denoted as T *D* base(*w*) ⊂ <sup>Σ</sup> ≀ , as follows. We have <sup>τ</sup>*<sup>p</sup>* ∈ <sup>T</sup> *D* base(*w*) if:

- <sup>τ</sup><sup>0</sup> = <sup>T</sup> <sup>∅</sup>(*w*),
- <sup>τ</sup><sup>0</sup> ⇒ ⋯ ⇒ <sup>τ</sup>*p*,
- there exists no <sup>τ</sup>*p*+<sup>1</sup> such that <sup>τ</sup>*<sup>p</sup>* ⇒ <sup>τ</sup>*p*+1.

That is, T *D* base(*w*) are the tokenizations of *<sup>w</sup>* which can be achieved by applying rules to an initial tokenization T <sup>∅</sup>(*w*) where all symbols in *<sup>w</sup>* are their own token, until a point where no further rules can be applied. Thus, to obtain one of the possible base tokenizations, we select non-deterministically a rule from *D* that can be applied to the current tokenization, until the set of rules that could be applied, is empty. Given that ∣<sup>T</sup> *D* base∣ ≥ 1, since there is non-deterministic choice in selecting the next applicable rule, a SentencePiece tokenizer [\[4\]](#page-11-4) is defined to remove ambiguity from the base tokenizer. We will (in a somewhat biased way) refer to this tokenization as the correct tokenization.

<span id="page-3-0"></span>Definition 3. The *SentencePiece* tokenization of *w*, denoted T *<sup>D</sup>*(*w*), also referred to as the *correct tokenization* of *<sup>w</sup>*, is <sup>τ</sup>*n*, with <sup>τ</sup>*<sup>n</sup>* ∈ <sup>T</sup> *D* base(*w*), where:

- <sup>τ</sup><sup>0</sup> = <sup>T</sup> <sup>∅</sup>(*w*);
- <sup>τ</sup><sup>0</sup> ⇒ ⋯ ⇒ <sup>τ</sup>*n*, and for 0 ≤ *<sup>i</sup>* < *<sup>n</sup>*, we pick the decomposition <sup>τ</sup>*<sup>i</sup>* = <sup>φ</sup> ≀*u*≀*v*≀<sup>φ</sup> ′ , to obtain <sup>τ</sup>*i*+<sup>1</sup> = <sup>φ</sup> ≀*uv*≀<sup>φ</sup> ′ , in such a way that:
  - *<sup>u</sup>*≀*<sup>v</sup>* is the highest priority rule in *<sup>D</sup>* for which such a decomposition exists;
  - among the remaining decompositions, we pick the unique one which minimizes ∣φ∣;
- no further rules apply to τ*n*.

Observe that T *<sup>D</sup>*(*w*) always exists, and is obtained, intuitively, as follows. Whenever it is possible to apply a rule from the dictionary *D* to merge some tokens in the interim tokenization, merge the *highestpriority* rule that occurs, and merge the left-most such pair if multiple occurrences exist. Note that this selects a unique tokenization, for each string *w*, from the set T *D base*(*w*).

*Example* <sup>1</sup>*.* Take the dictionary *<sup>D</sup>* = [*a*≀*b*,*a*≀*bc*,*b*≀*c*,*ab*≀*c*], then the correct tokenization of the string *abcbcab* is *abc*≀*bc*≀*ab*, using the following steps:

- Initially, <sup>τ</sup><sup>0</sup> = *<sup>a</sup>*≀*b*≀*c*≀*b*≀*c*≀*a*≀*<sup>b</sup>*, *<sup>a</sup>*≀*<sup>b</sup>* ∈ *<sup>D</sup>* applies to the leftmost *<sup>a</sup>*≀*b*, producing <sup>τ</sup><sup>1</sup> = *ab*≀*c*≀*b*≀*c*≀*a*≀*<sup>b</sup>*.
- The rule *<sup>a</sup>*≀*<sup>b</sup>* still applies, now to the last two tokens, producing <sup>τ</sup><sup>2</sup> = *ab*≀*c*≀*b*≀*c*≀*ab*. The rule *<sup>a</sup>*≀*<sup>b</sup>* now no longer applies anywhere.
- The next rule *<sup>a</sup>*≀*bc* does not apply, as there is no token *bc*, but *<sup>b</sup>*≀*<sup>c</sup>* does apply, producing <sup>τ</sup><sup>3</sup> = *ab*≀*c*≀*bc*≀*ab*.
- The first rule that can now be applied is the rule *ab*≀*c*, producing <sup>τ</sup><sup>4</sup> = *abc*≀*bc*≀*ab*. Now, no further rules apply, so *abc*≀*bc*≀*ab* is the correct (SentencePiece) tokenization.

<span id="page-3-2"></span>It is interesting to observe that the rule *<sup>a</sup>*≀*bc* has the second-highest priority in the dictionary, but was never applied. Also, when using the base tokenizer, *<sup>a</sup>*≀*bc* can certainly be applied when tokenizing the string *abcbcab*. Observe that applying *<sup>a</sup>*≀*bc* would produce the token *abc*, but tokenizing the string *abc* takes the steps *<sup>a</sup>*≀*b*≀*<sup>c</sup>* ⇒ *ab*≀*<sup>c</sup>* ⇒ *abc*. Later on in Corollary [1](#page-6-0) we show that a rule *<sup>u</sup><sup>i</sup>* ≀*vi* is *useful*, i.e. gets applied in the tokenization of some string, if and only if it gets applied when tokenizing the string *uiv<sup>i</sup>* . ◇ *Example* <sup>2</sup>*.* Take the dictionary *<sup>D</sup>* = [*c*≀*ab*,*ab*≀*c*,*a*≀*b*]. Then the correct tokenization of *abcabcabcabc* is *abc*≀*abc*≀*abc*≀*abc*. Notice that this tokenization is achieved left to right. After five steps, we have the tokenization *abc*≀*abc*≀*ab*≀*c*≀*a*≀*b*≀*c*. Contrast this to tokenizing the string *bcabcabcabc* (i.e. we delete the initial *<sup>a</sup>*) which tokenizes as *<sup>b</sup>*≀*cab*≀*cab*≀*cab*≀*c*, or *cabcabcabcabc* (i.e. adding an initial *<sup>c</sup>*), which leads to *cab*≀*cab*≀*cab*≀*cab*≀*c*, where we need to move left to apply *<sup>c</sup>*≀*ab*, after having applied *<sup>a</sup>*≀*b*. This illustrates that a small modification to the string can cause an arbitrarily large change to the resulting tokenization (to the right). ◇

Interestingly enough, not all tokenization libraries modify the base tokenizer in the same way in order to eliminate ambiguity of tokenization. Let us consider the Python implementation of the GPT-2 tokenizer offered by HuggingFace [\[2\]](#page-11-7), which removes ambiguity from the base tokenizer, as follows.

<span id="page-3-1"></span>Definition 4. The *HuggingFace tokenization* τ*<sup>n</sup>* of *w*, which we denote by <sup>T</sup> *D* hf(*w*) ∈ <sup>T</sup> *D* base(*w*), is defined as follows, where <sup>τ</sup><sup>0</sup> = <sup>T</sup> <sup>∅</sup>(*w*). In <sup>τ</sup><sup>0</sup> ⇒<sup>+</sup> ⋯ ⇒<sup>+</sup> <sup>τ</sup>*n*, for 0 ≤ *<sup>i</sup>* < *<sup>n</sup>*, we select a decomposition <sup>τ</sup>*<sup>i</sup>* = <sup>φ</sup> ≀*u*≀*v*≀<sup>φ</sup> ′ , such that *<sup>u</sup>*≀*<sup>v</sup>* ∈ *<sup>D</sup>* is the highest priority rule applicable to <sup>τ</sup>*<sup>i</sup>* , and then apply *<sup>u</sup>*≀*<sup>v</sup>* from left to right, until it is no longer applicable, in order to obtain the unique τ*i*+1.

That is, in both Definitions [3](#page-3-0) and [4](#page-3-1) we rewrite τ*<sup>i</sup>* by picking the highest-priority applicable rule and applying it at the left-most possible position. However, the SentencePiece semantics picks the highestpriority applicable rule in *every* step, where HuggingFace picks a rule and uses it until it becomes inapplicable. This does create a formal difference in semantics, but as we will see they differ only in cases which may be considered degenerate given the way dictionaries are usually constructed.

*Example* <sup>3</sup>*.* Take the dictionary *<sup>D</sup>* = [*ab*≀*a*,*a*≀*b*] and consider the tokenization of *<sup>w</sup>* = *abababab*, which has T *<sup>D</sup>*(*w*) = *aba*≀*b*≀*aba*≀*b*, but <sup>T</sup> *D* hf(*w*) = *ab*≀*ab*≀*ab*≀*ab*. ◇

<span id="page-4-0"></span>*Remark* 1*.* The reason why the *D* in the previous example is regarded to be degenerate or improper, is that a byte pair dictionary is typically produced [\[7\]](#page-11-2) by taking a training corpus, initially tokenizing it symbol by symbol, and then iteratively adding the most common token pair to the dictionary, tokenizing, and repeating. For example, in the training corpus *<sup>a</sup>*≀*b*≀*c*≀*a*≀*b*≀*c*≀*a*≀*c*≀*a*, the most common token pair is *<sup>c</sup>*≀*a*, which is inserted as the first rule in the dictionary. Then, we continue using *<sup>a</sup>*≀*b*≀*ca*≀*b*≀*ca*≀*ca*. Now, the most common pair is *<sup>b</sup>*≀*ca*, and this rule is added to the dictionary, which now consists of the rules [*c*≀*a*,*b*≀*ca*]. The new dictionary now produces *<sup>a</sup>*≀*bca*≀*bca*≀*ca*, as tokenization, and so on. Observe that when constructing a dictionary in this way, a rule *u<sup>i</sup>* ≀*<sup>v</sup><sup>i</sup>* cannot have higher priority than the rules needed to produce *u<sup>i</sup>* and *v<sup>i</sup>* , a property formalized in the next definition. Also, when tokenizing the training corpus with the dictionary obtained through training, using HuggingFace semantics, the tokenization obtained will be the tokenization of the training corpus at the end of the training process, and each rule in the dictionary will be used in this tokenization. ◇

Definition 5. A dictionary *<sup>D</sup>* = [*<sup>u</sup>*<sup>1</sup> ≀*<sup>v</sup>*1,...*u<sup>i</sup>* ≀*vi* ,...,*u<sup>j</sup>* ≀*vj* ,...,*u<sup>n</sup>* ≀*<sup>v</sup>n*] is *proper* if for each *<sup>j</sup>* with ∣*<sup>u</sup><sup>j</sup>* ∣ > 1, there exists *<sup>i</sup>* < *<sup>j</sup>* such that *<sup>u</sup><sup>j</sup>* = *<sup>u</sup>iv<sup>i</sup>* , and similarly, for each *j* ′ with ∣*<sup>v</sup><sup>j</sup>* ′∣ > 1, there exists *<sup>i</sup>* ′ < *<sup>j</sup>* ′ such that *vj* ′ = *<sup>u</sup><sup>i</sup>* ′*vi* ′.

Note that a proper dictionary may still contain rules which are not useful. Consider for example the dictionary *<sup>D</sup>* = [*b*≀*c*,*a*≀*b*,*c*≀*d*,*ab*≀*cd*]. Then *<sup>D</sup>* is proper, but *ab*≀*cd* is not useful. This can be seen by noting that when T <sup>∅</sup>(*w*) equals *<sup>a</sup>*≀*b*≀*c*≀*d*, then the first rule gets applied to produce *<sup>a</sup>*≀*bc*≀*d*, and thus it is not possible to apply the rules *<sup>a</sup>*≀*<sup>b</sup>* and *<sup>c</sup>*≀*d*, in order so that *ab*≀*cd* could be applied. But note that if *<sup>D</sup>* is constructed from a training corpus, then *D* is proper and each rule in *D* is useful.

With the additional assumption that the dictionary is proper, the SentencePiece and HuggingFace tokenizers turn out to have equivalent semantics. This should to some extent be expected, as they are intended to achieve the same results, the HuggingFace approach effectively being a small simplification.

<span id="page-4-1"></span>Lemma 1. *If D is proper, we have* T *<sup>D</sup>*(*w*) = <sup>T</sup> *D hf*(*w*) *for all w.*

*Proof.* By contradiction, assume that some *w* has T *<sup>D</sup>*(*w*) ≠ <sup>T</sup> *D* hf(*w*). Let <sup>τ</sup><sup>0</sup> ⇒ ⋯ ⇒ <sup>τ</sup>*<sup>n</sup>* be the tokenization steps taken by T *<sup>D</sup>*(*w*), and <sup>φ</sup><sup>0</sup> ⇒ ⋯ ⇒ <sup>φ</sup>*<sup>m</sup>* the tokenization steps taken by <sup>T</sup> *D* hf. Let *i* be the smallest index such that <sup>τ</sup>*<sup>i</sup>* ≠ <sup>φ</sup>*<sup>i</sup>* . Note, such an *i* must exist, otherwise, one sequence would be a subsequence of the other, which is impossible by Definition [2.](#page-2-0) Thus, one sequence cannot be a proper prefix of the other. We also have *<sup>i</sup>* ≥ 2, as the semantics differ only in that Definition [4](#page-3-1) prefers repeating the previous rule over the highest priority one, but this difference can only be exhibited when there is a previous step to repeat.

We then have <sup>τ</sup>*i*−<sup>2</sup> = <sup>φ</sup>*<sup>i</sup>*−2, <sup>τ</sup>*i*−<sup>1</sup> = <sup>φ</sup>*<sup>i</sup>*−<sup>1</sup> and <sup>τ</sup>*<sup>i</sup>* ≠ <sup>φ</sup>*<sup>i</sup>* . Let *<sup>r</sup>*<sup>0</sup> be the rule applied in <sup>τ</sup>*i*−<sup>2</sup> ⇒ <sup>τ</sup>*i*−<sup>1</sup> (and <sup>φ</sup>*<sup>i</sup>*−<sup>2</sup> ⇒ <sup>φ</sup>*<sup>i</sup>*−<sup>1</sup> as they are equal), *<sup>r</sup>*<sup>1</sup> the rule in <sup>τ</sup>*i*−<sup>1</sup> ⇒ <sup>τ</sup>*<sup>i</sup>* , and *<sup>r</sup>*<sup>2</sup> the rule in <sup>τ</sup>*i*−<sup>1</sup> ⇒ <sup>φ</sup>*<sup>i</sup>* . That is, with some abuse of notation, the following situation:

$$\cdots \Rightarrow (\tau_{i-2} = \phi_{i-2}) \xrightarrow{r_0} (\tau_{i-1} = \phi_{i-1}) \xrightarrow{r_1} \tau_i \Rightarrow \cdots$$

Then we know that *r*<sup>1</sup> has higher priority than *r*2, since they must differ, and Definition [3](#page-3-0) (SentencePiece) always picks the highest priority rule applicable. The only possible reason for them to differ is that *<sup>r</sup>*<sup>0</sup> = *<sup>r</sup>*2, i.e. the Definition [4](#page-3-1) (HuggingFace) semantics prioritized using the same rule as in the previous step. However, as they agree in the previous step this means that we picked *r*<sup>0</sup> in that step by virtue of Definition [3,](#page-3-0) even though *r*<sup>1</sup> has higher priority than *r*0, which must mean that *r*<sup>1</sup> was *not* applicable before. This leads to a contradiction, as applying *r*<sup>0</sup> must then have created a token which made *r*<sup>1</sup> applicable, which, since *r*<sup>0</sup> is of lower priority, contradicts *D* being a proper dictionary. As such, our assumption was wrong and T *D* hf(*w*) = <sup>T</sup> *<sup>D</sup>*(*w*) by necessity.

With this result in hand, it becomes less relevant to differentiate between the two semantics whenever considering only proper dictionaries.

*Remark* <sup>2</sup>*.* It can be decided whether *<sup>D</sup>* is proper in time O(∥*D*∥ 2 ) (assuming ∣*uv*∣ is constant for all rules *<sup>u</sup>*≀*<sup>v</sup>* in *<sup>D</sup>*), where ∥*D*∥ = ∑{∣*uv*∣ ∣ *<sup>u</sup>*≀*<sup>v</sup>* ∈ *<sup>D</sup>*}. For each *<sup>u</sup>*≀*<sup>v</sup>* ∈ *<sup>D</sup>*, determine all *<sup>u</sup>* ′ ≀*v* ′ such that *uv* is a substring of *u* ′ or *v* ′ , and for all such rules *u* ′ ≀*v* ′ , verify that *<sup>u</sup>*≀*<sup>v</sup>* has lower priority than *<sup>u</sup>* ′ ≀*v* ′ . ◇

Next, we investigate the relationship between the tokenization of substrings of *w*, and the tokenization of *w*. First, we consider the following example. Let *u*,*v* be strings with T *<sup>D</sup>*(*u*) = <sup>τ</sup><sup>1</sup> ≀<sup>τ</sup><sup>2</sup> and <sup>T</sup> *<sup>D</sup>*(*v*) = <sup>φ</sup><sup>1</sup> ≀<sup>φ</sup>2. Then it is not necessarily the case that τ<sup>1</sup> ≀<sup>φ</sup><sup>2</sup> = <sup>T</sup> *<sup>D</sup>*(π(<sup>τ</sup><sup>1</sup> ≀<sup>φ</sup>2)) or that <sup>φ</sup><sup>1</sup> ≀<sup>τ</sup><sup>2</sup> = <sup>T</sup> *<sup>D</sup>*(π(<sup>φ</sup><sup>1</sup> ≀<sup>τ</sup>2)). An easy counterexample is obtained by letting *<sup>D</sup>* = [*a*≀*a*,*b*≀*b*], <sup>τ</sup><sup>1</sup> = *<sup>a</sup>*, <sup>τ</sup><sup>2</sup> = *<sup>b</sup>*, <sup>φ</sup><sup>1</sup> = *<sup>b</sup>*, and <sup>φ</sup><sup>2</sup> = *<sup>a</sup>*. Observe that indeed T *<sup>D</sup>*(*ab*) = *<sup>a</sup>*≀*<sup>b</sup>* = <sup>τ</sup><sup>1</sup> ≀<sup>τ</sup>2, and <sup>T</sup> *<sup>D</sup>*(*ba*) = *<sup>b</sup>*≀*<sup>a</sup>* = <sup>φ</sup><sup>1</sup> ≀<sup>φ</sup>2, *however* <sup>τ</sup><sup>1</sup> ≀<sup>φ</sup><sup>2</sup> = *<sup>a</sup>*≀*<sup>a</sup>* ≠ <sup>T</sup> *<sup>D</sup>*(*aa*) and <sup>φ</sup><sup>1</sup> ≀<sup>τ</sup><sup>2</sup> = *<sup>b</sup>*≀*<sup>b</sup>* ≠ <sup>T</sup> *<sup>D</sup>*(*bb*). This shows that tokenizations can not be decomposed and then again glued together in arbitrary ways. However, deriving the tokenization of substrings of a given string *w*, given the final full tokenization of *w*, is sometimes possible, as shown in the following lemma.

<span id="page-5-0"></span>Lemma 2. *Tokenization derivations and tokenizations have the following properties:*

- *(i) For both SentencePiece and HuggingFace, if* φ<sup>1</sup> ≀ ... ≀<sup>φ</sup>*<sup>k</sup>* ⇒<sup>∗</sup> <sup>φ</sup> ′ 1 ≀ ... ≀<sup>φ</sup> ′ *k , then if* <sup>π</sup>(<sup>φ</sup>*i*) = <sup>π</sup>(<sup>φ</sup> ′ *i* ) *for all i, we have that* <sup>φ</sup>*<sup>i</sup>* ⇒<sup>∗</sup> <sup>φ</sup> ′ *i for all i.*
- *(ii) For a dictionary D and string w such that* T *<sup>D</sup>*(*w*) = <sup>τ</sup><sup>1</sup> ≀ ... ≀<sup>τ</sup>*<sup>k</sup> (or* <sup>T</sup> *D h f* (*w*) = <sup>τ</sup><sup>1</sup> ≀ ... ≀<sup>τ</sup>*k), it holds that* T *<sup>D</sup>*(π(<sup>τ</sup>*i*)) = <sup>τ</sup>*<sup>i</sup> (respectively* <sup>T</sup> *D h f* (π(<sup>τ</sup>*i*)) = <sup>τ</sup>*i).*

*Proof.* For (i), let φ1,<sup>1</sup> ≀ ... ≀<sup>φ</sup>*k*,<sup>1</sup> ⇒ ⋯ ⇒ <sup>φ</sup>1,*<sup>n</sup>* ≀ ... ≀<sup>φ</sup>*k*,*<sup>n</sup>* be the steps taken by the procedure in Definition [2,](#page-2-0) such that <sup>φ</sup>*i*,<sup>1</sup> = <sup>φ</sup>*<sup>i</sup>* and <sup>φ</sup>*i*,*<sup>n</sup>* = <sup>φ</sup> ′ *i* for all *<sup>i</sup>*, and <sup>π</sup>(<sup>φ</sup>*i*, *<sup>j</sup>*) = <sup>π</sup>(<sup>φ</sup>*i*, *<sup>j</sup>* ′) for all *<sup>i</sup>*, *<sup>j</sup>* and *<sup>j</sup>* ′ . Removing all duplicates from φ*i*,1,...,φ*i*,*<sup>n</sup>* produces the sequence of steps taken by SentencePiece or HuggingFace derivations, i.e. in each step we apply the highest-priority rule from *D* as left-most as possible, in the case of SentencePiece semantics, and we apply the highest-priority rule as many times as possible, in the case of HuggingFace semantics.

For (ii), take <sup>φ</sup>*<sup>i</sup>* = <sup>T</sup>

<sup>∅</sup>(<sup>τ</sup>*i*) and <sup>φ</sup>

′ *<sup>i</sup>* = <sup>τ</sup>*<sup>i</sup>*

in (i).

<span id="page-5-1"></span>*Remark* 3*.* A trivial outcome of this lemma is then that one can freely truncate tokenizations. I.e. if we have tokenized a long text *w* and are only interested in a prefix, we can pick a suitable prefix of the tokenization (not the string) and it will be correct for the string it represents. A similar remark holds for a suffix of a tokenization.

<span id="page-6-0"></span>Corollary 1. *For SentencePiece or HuggingFace semantics, a rule in a dictionary D is useful if and only if it gets applied when tokenizing the string it produces.*

*Proof.* The "if" part follows directly from the definition of useful, so for the converse, assume we have a derivation α<sup>1</sup> ≀⋯≀<sup>α</sup>*<sup>n</sup>* ⇒⋯⇒<sup>φ</sup> ≀*u*≀*v*≀<sup>φ</sup> ′ ⇒<sup>φ</sup> ≀*uv*≀<sup>φ</sup> ′ . But then the previous lemma implies that T <sup>∅</sup>(*uv*)⇒<sup>∗</sup> *<sup>u</sup>*≀*<sup>v</sup>* ⇒ *uv*.

The main purpose of Lemma [2](#page-5-0) is that it makes it possible to do tokenizations in streaming and incremental ways. Algorithm [1](#page-6-1) below shows how this is achieved, but in order to establish the correctness of this algorithm, we first need the following corollary, which shows how we can split and then glue tokenizations.

<span id="page-6-2"></span>Corollary 2. *If* T *<sup>D</sup>*(*v*) = <sup>τ</sup><sup>1</sup> ≀*u*≀<sup>τ</sup><sup>2</sup> *and* <sup>T</sup> *<sup>D</sup>*(*w*) = <sup>φ</sup><sup>1</sup> ≀*u*≀<sup>φ</sup><sup>2</sup> *then we also have* <sup>T</sup> *<sup>D</sup>*(π(<sup>τ</sup><sup>1</sup> ≀*u*≀<sup>φ</sup>2)) = <sup>τ</sup><sup>1</sup> ≀*u*≀<sup>φ</sup><sup>2</sup> *and* T *<sup>D</sup>*(π(<sup>φ</sup><sup>1</sup> ≀*u*≀<sup>τ</sup>2)) = <sup>φ</sup><sup>1</sup> ≀*u*≀<sup>τ</sup>2*. The same result holds for the HuggingFace semantics.*

*Proof.* Remark [3](#page-5-1) give us that T *<sup>D</sup>*(π(<sup>τ</sup><sup>1</sup> ≀*u*)) = <sup>τ</sup><sup>1</sup> ≀*u*,<sup>T</sup> *<sup>D</sup>*(π(*u*≀<sup>τ</sup>2)) = *<sup>u</sup>*≀<sup>τ</sup><sup>2</sup> and similarly <sup>T</sup> *<sup>D</sup>*(π(<sup>φ</sup><sup>1</sup> ≀*u*)) = φ1 ≀*u*,<sup>T</sup> *<sup>D</sup>*(π(*u*≀<sup>φ</sup>2)) = *<sup>u</sup>*≀<sup>φ</sup><sup>2</sup> where *<sup>u</sup>*, <sup>τ</sup>1, <sup>φ</sup>1, <sup>τ</sup>1, and <sup>τ</sup><sup>2</sup> are as in the corollary above. The result now follows from the observation that we can glue two tokenizations together, if the end token of the first tokenization is the same as the start token of the next tokenization. The same argument holds for HuggingFace semantics. This follows the same line of argument as Lemma [2,](#page-5-0) except instead of pruning steps from one tokenization, we interleave the steps of two, deduplicating rules applied to the overlapping token. The overlapping token ensures that one tokenization cannot "disturb" the other.

With this in hand we can define an incremental update algorithm, which is not necessarily efficient in general (due to cases like Example [2\)](#page-3-2), but will often do much less work than full retokenization, if we are in a situation where steps 4 and 5 are performed only a few times, i.e. if *i* is close to *n* and *j* close to 1 when the condition 'If (*v*<sup>1</sup> = *<sup>u</sup><sup>i</sup>* or *<sup>i</sup>* = 1) and (*v<sup>k</sup>* = *<sup>u</sup>* ′ *j* or *<sup>j</sup>* = *<sup>m</sup>*)' in step 3 holds. When showing the correctness of Algorithm [1](#page-6-1) below, we will use the special case of the previous corollary where τ<sup>1</sup> and φ<sup>2</sup> are empty tokenizations, or τ<sup>2</sup> and φ<sup>1</sup> are empty.

<span id="page-6-1"></span>Algorithm 1. Given T *<sup>D</sup>*(*w*) = <sup>τ</sup> and <sup>T</sup> *<sup>D</sup>*(*<sup>w</sup>* ′ ) = <sup>τ</sup> ′ we compute the tokenization <sup>T</sup> *<sup>D</sup>*(*ww*′ ) in the following way, assuming we are not in the trivial case where *<sup>w</sup>* = <sup>ε</sup> or *<sup>w</sup>* ′ = <sup>ε</sup>.

- 1. Let <sup>τ</sup> = *<sup>u</sup>*<sup>1</sup> ≀⋯≀*<sup>u</sup><sup>n</sup>* and <sup>τ</sup> ′ = *<sup>u</sup>* ′ 1 ≀⋯≀*<sup>u</sup>* ′ *<sup>m</sup>*, initialize *<sup>i</sup>* = *<sup>n</sup>* and *<sup>j</sup>* = 1.
- 2. Compute T *<sup>D</sup>*(*<sup>u</sup>i*⋯*<sup>u</sup>n<sup>u</sup>* ′ <sup>1</sup>⋯*<sup>u</sup>* ′ *j* ) = *<sup>v</sup>*<sup>1</sup> ≀⋯≀*<sup>v</sup>k*.
- 3. If (*v*<sup>1</sup> = *<sup>u</sup><sup>i</sup>* or *<sup>i</sup>* = 1) and (*v<sup>k</sup>* = *<sup>u</sup>* ′ *j* or *<sup>j</sup>* = *<sup>m</sup>*) output *<sup>u</sup>*<sup>1</sup> ≀⋯≀*<sup>u</sup><sup>i</sup>* ≀*v*2 ≀⋯≀*<sup>v</sup>k*−<sup>1</sup> ≀*u* ′ *j* ≀⋯≀*<sup>u</sup>* ′ *<sup>m</sup>* as <sup>T</sup> *<sup>D</sup>*(*ww*′ ) and halt.
- 4. If *<sup>u</sup><sup>i</sup>* ≠ *<sup>v</sup>*<sup>1</sup> and *<sup>i</sup>* > 1, then *<sup>i</sup>* ← *<sup>i</sup>*−1.
- 5. If *u* ′ *<sup>j</sup>* ≠ *<sup>v</sup><sup>k</sup>* and *<sup>j</sup>* < *<sup>m</sup>*, then *<sup>j</sup>* ← *<sup>j</sup>*+1.
- 6. Go to step 2.

Theorem 1. *Algorithm [1](#page-6-1) is correct.*

*Proof.* This amounts to two applications of Corollary [2.](#page-6-2) The algorithm halts in a state where both *u*1 ≀⋯≀*<sup>u</sup><sup>i</sup>* and *<sup>v</sup>*<sup>1</sup> ≀⋯≀*<sup>v</sup><sup>k</sup>* are correct tokenizations, the former holds by Remark [3](#page-5-1) and the latter by construction. We also have *<sup>u</sup><sup>i</sup>* = *<sup>v</sup>*<sup>1</sup> (either that or *<sup>i</sup>* = 1, but that case is trivial), which allows the application of Corollary [2](#page-6-2) to establish that τ<sup>1</sup> ≀*ui* ≀*v*2 ≀⋯≀*<sup>v</sup><sup>k</sup>* is a correct tokenization. To make this specific, in the terms of Corollary [2](#page-6-2) we have <sup>τ</sup><sup>2</sup> = <sup>φ</sup><sup>1</sup> = <sup>ε</sup>, *<sup>u</sup>* = *<sup>u</sup><sup>i</sup>* = *<sup>v</sup>*1, <sup>τ</sup><sup>1</sup> = *<sup>u</sup>*<sup>1</sup> ≀ ... ≀*<sup>u</sup>i*−1, and <sup>φ</sup><sup>2</sup> = *<sup>v</sup>*<sup>2</sup> ≀⋯≀*<sup>v</sup>k*, which gives us that τ<sup>1</sup> ≀*u*≀<sup>φ</sup><sup>2</sup> = *<sup>u</sup>*<sup>1</sup> ≀⋯*<sup>u</sup><sup>i</sup>* ≀*v*2 ≀⋯≀*<sup>v</sup><sup>k</sup>* is a correct tokenization. Now repeat this argument for the suffix to complete the proof.

Remark [3](#page-5-1) and Algorithm [1](#page-6-1) give tools to perform arbitrary incremental updates. For example, assume we have the tokenization <sup>τ</sup> of a (long) string *<sup>w</sup>*, and we make a small change in *<sup>w</sup>*, let's say *<sup>w</sup>* = *<sup>v</sup>*1α*v*<sup>2</sup> and the updated string is *w* ′ = *<sup>v</sup>*1β*v*2. Then let <sup>τ</sup><sup>1</sup> be the prefix of <sup>τ</sup> which falls entirely within *<sup>v</sup>*1, let <sup>τ</sup><sup>2</sup> be the suffix of <sup>τ</sup> which falls entirely inside *<sup>v</sup>*2, let *<sup>u</sup>* be the string such that <sup>π</sup>(<sup>τ</sup>1)*<sup>u</sup>*π(<sup>τ</sup>2) = *<sup>w</sup>* ′ , then compute <sup>φ</sup> = <sup>T</sup> *<sup>D</sup>*(*u*), and obtain the tokenization of *<sup>w</sup>* ′ by applying Algorithm [1](#page-6-1) to concatenate τ<sup>1</sup> to φ, and then that tokenization to τ2.

Unfortunately, Algorithm [1](#page-6-1) is not *necessarily* more efficient than retokenizing the whole string, and might be worse. Of course, an experimental bound can be used in steps 3 and 4, where once we have decreased *i* and increased *j*, more times than the specified bound, we fall back to retokenizing the complete string. In cases where there is a subset of symbols Σ ′ from Σ, where symbols from Σ ′ can only appear as the first or last symbols in *uv* for rules *<sup>u</sup>*≀*v*, and in all input strings there is a relatively small distance between symbols in Σ ′ (i.e. input is not selected from all of Σ ∗ ), we certainly have that Algorithm [1](#page-6-1) is much more efficient than retokenizing the whole string. In general, it seems likely that steps 4 and 5 in Algorithm [1](#page-6-1) will be performed relatively few times in most practical dictionaries, but investigating this, is left for future work. We consider the worst-case in more generality in the next section. We establish a bound on how many times *i* can be decremented determined solely by the dictionary (so a constant in the length of the string). Thus, we consider the worst-case when modifications happen late in a string, for example when applying appends.

## 4 Tokenizing Online with Finite Lookahead

In this section, we assume all dictionaries are proper (although at times we do state this explicitly, to emphasize that we are making this assumption), so by Lemma [1](#page-4-1) T *<sup>D</sup>* and <sup>T</sup> *D* hf are interchangeable. We investigate the following question: When we tokenize a string, in a streaming fashion, how long is the suffix that we need to tokenize again, when we resume tokenization, given we make no assumptions about the input string being tokenized. We refer to this constant as the *lookahead constant* for a dictionary *D*, and denote it by *<sup>l</sup>*(*D*). More formally, we have the following definition.

<span id="page-7-0"></span>Definition 6. Let *<sup>D</sup>* be proper and <sup>φ</sup>,<sup>τ</sup> and <sup>ψ</sup> be tokenizations. Then *<sup>l</sup>*(*D*), the *lookahead constant* for *<sup>D</sup>*, is the smallest constant such that if ∣π(τ)∣ ≥ *<sup>l</sup>*(*D*) and <sup>T</sup> *<sup>D</sup>*(π(φ)π(τ)) = <sup>φ</sup> ≀τ, then <sup>T</sup> *<sup>D</sup>*(π(<sup>φ</sup> ≀τ)π(ψ)) = <sup>φ</sup> ≀<sup>ψ</sup> ′ , for some tokenization ψ ′ .

We show in Theorem [2,](#page-8-0) that *<sup>l</sup>*(*D*) ≤ ∣*D*∣ ⋅max{∣*uv*∣ ∣ *<sup>u</sup>*≀*<sup>v</sup>* ∈ *<sup>D</sup>*}, where ∣*D*∣ is the number of rules in *<sup>D</sup>*. After this, in Remark [5,](#page-10-0) we explore how to improve on this bound.

The next lemma will be used in Theorem [2](#page-8-0) to perform HuggingFace tokenization in a straightforward inductive way, where for a proper dictionary *<sup>D</sup>* = [*<sup>u</sup>*<sup>1</sup> ≀*<sup>v</sup>*1,...,*u<sup>n</sup>* ≀*<sup>v</sup>n*] we can tokenize a string by first applying the rule *u*<sup>1</sup> ≀*<sup>v</sup>*<sup>1</sup> as many times as possible, then the rule *<sup>u</sup>*<sup>2</sup> ≀*<sup>v</sup>*<sup>2</sup> as many times as possible, and so on.

<span id="page-7-1"></span>Lemma 3. *Let D be proper dictionary and* T *D hf*(*w*) = <sup>τ</sup>*. Assume r*1,...,*r<sup>n</sup> is the sequence of rules applied to produce* τ *according to Definition [4](#page-3-1) (i.e. using HuggingFace semantics). Then it must be the case that r*1,...,*r<sup>n</sup> are in order of decreasing priority.*

*Proof.* We proceed in a way similar to Lemma [1.](#page-4-1) By contradiction, assume that there exists some *r<sup>i</sup>* such that *ri*+<sup>1</sup> is of higher priority than *r<sup>i</sup>* . This means that the tokenization after the first *i* steps contains the pair *<sup>r</sup>i*+<sup>1</sup> = *<sup>u</sup>*≀*v*, but this pair cannot have been created by the applications of *<sup>r</sup><sup>i</sup>* , as it is of lower priority than *ri*+<sup>1</sup> and *D* is proper, and it also cannot have existed in the tokenization when *r<sup>i</sup>* was picked as the rule to next apply, as that contradicts how rules are picked in Definition [4.](#page-3-1) As such, our assumption was wrong, and *r<sup>i</sup>* is of higher priority or equal to *ri*+1.

We will use the term *refinement* for the way a tokenization is developed in this way, i.e. a *tokenization* τ *is a refinement of* τ ′ , if τ ′ can be obtained from τ by applying π to some of the subtokenizations in <sup>τ</sup>. For example, <sup>φ</sup> ≀<sup>φ</sup> ′ ≀φ ′′ is a refinement of <sup>φ</sup> ≀π(<sup>φ</sup> ′ )≀φ ′′ and also of <sup>π</sup>(φ)≀π(<sup>φ</sup> ′ )≀φ ′′. We can also consider the opposite notion, i.e. a tokenization τ ′ is *coarser* than τ , if τ is a refinement of τ ′ . Thus, a (final) tokenization of a given string is obtained by using rules from *D* to obtain coarser and coarser tokenizations. Recall, ∣*D*∣ denotes the number of rules in *<sup>D</sup>*.

<span id="page-8-0"></span>Theorem 2. *Let D be proper,* ∣τ∣ ≥ ∣*D*∣ *and* <sup>T</sup> *<sup>D</sup>*(π(φ)π(τ)) = <sup>φ</sup> ≀τ*. Then* <sup>T</sup> *<sup>D</sup>*(π(<sup>φ</sup> ≀τ)π(ψ)) = <sup>φ</sup> ≀<sup>ψ</sup> ′ *, for some tokenization* ψ ′ *. That is, by Definition [6](#page-7-0) we have l*(*D*) ≤ ∣*D*∣ ⋅max{∣*uv*∣ ∣ *<sup>u</sup>*≀*<sup>v</sup>* ∈ *<sup>D</sup>*}*.*

*Proof.* This is easier to see using T *D* hf, which is equivalent to <sup>T</sup> *<sup>D</sup>* by Lemma [1.](#page-4-1) Let *D* be the dictionary [*u*1 ≀*<sup>v</sup>*1,...,*u<sup>n</sup>* ≀*<sup>v</sup>n*] and *<sup>D</sup><sup>i</sup>* be the *<sup>i</sup>*-length prefix of *<sup>D</sup>*, i.e. *<sup>D</sup><sup>i</sup>* = [*<sup>u</sup>*<sup>1</sup> ≀*<sup>v</sup>*1,...,*u<sup>i</sup>* ≀*<sup>v</sup>i*] for each *<sup>i</sup>*. We determine T *D* hf(*w*) as follows: First calculate <sup>T</sup> *D*<sup>1</sup> hf (*w*), then assuming we know <sup>T</sup> *Di* hf , we apply *ui*+<sup>1</sup> ≀*<sup>v</sup>i*+<sup>1</sup> to <sup>T</sup> *Di* hf (*w*) wherever possible (working left to right) to obtain T *Di*+<sup>1</sup> hf . This procedure is correct by Lemma [3.](#page-7-1) We refer to T *<sup>D</sup>i*(*w*) as a tokenization at level *<sup>i</sup>*, and note that <sup>T</sup> *<sup>D</sup>i*(*w*) is a refinement of <sup>T</sup> *<sup>D</sup>*(*w*).

Let <sup>φ</sup> ≀<sup>τ</sup> = *<sup>w</sup>*<sup>1</sup> ≀ ... ≀*<sup>w</sup><sup>k</sup>* and *<sup>w</sup>* = <sup>π</sup>(<sup>φ</sup> ≀τ)π(ψ). We show that the tokenization of *<sup>w</sup>* at level *<sup>i</sup>* is a refinement of a tokenization of the form *w*<sup>1</sup> ≀ ... ≀*<sup>w</sup>k*−*<sup>i</sup>* ≀ψ*i* , thus that T *Di* hf (*w*) is a refinement of a tokenization of the form *w*<sup>1</sup> ≀ ... ≀*<sup>w</sup>k*−*<sup>i</sup>* ≀ψ*i* , for some tokenization ψ*<sup>i</sup>* . More precisely, when we use the dictionary *D<sup>i</sup>* , then tokenizing <sup>π</sup>(<sup>φ</sup> ≀τ)π(ψ), instead of only <sup>π</sup>(<sup>φ</sup> ≀τ), changes at most the rightmost *<sup>i</sup>* tokens in <sup>φ</sup> ≀τ. This implies that when *<sup>i</sup>* = *<sup>n</sup>*, we obtain that <sup>T</sup> *D<sup>n</sup>* hf (*w*) is a tokenization of the form *<sup>w</sup>*<sup>1</sup> ≀ ... ≀*<sup>w</sup>k*−*<sup>n</sup>* ≀<sup>ψ</sup>*n*, i.e. not only a refinement of a tokenization of the given form.

First, we show that T *D*<sup>1</sup> hf (*w*) is a refinement of a tokenization of the form *<sup>w</sup>*<sup>1</sup> ≀ ... ≀*<sup>w</sup>k*−<sup>1</sup> ≀<sup>ψ</sup>1. Note that *u*1 ≀*<sup>v</sup>*<sup>1</sup> could potentially be applied to the substring *<sup>w</sup>k*<sup>π</sup>(ψ), when tokenizing <sup>π</sup>(<sup>φ</sup> ≀τ)π(ψ), but *<sup>u</sup>*<sup>1</sup> ≀*<sup>v</sup>*<sup>1</sup> is not applied across any of the (*<sup>k</sup>* −1) boundaries between tokens in *<sup>w</sup>*<sup>1</sup> ≀ ... ≀*<sup>w</sup>k*. This must be the case, otherwise *u*<sup>1</sup> ≀*<sup>v</sup>*<sup>1</sup> would have been applied over some of these (*k*−1) boundaries between the tokens *<sup>w</sup><sup>i</sup>* , for 1 ≤ *<sup>i</sup>* ≤ *<sup>k</sup>*, when computing the tokenization *<sup>w</sup>*<sup>1</sup> ≀ ... ≀*<sup>w</sup><sup>k</sup>* with the full dictionary *<sup>D</sup>*.

Moving on to the next rule in terms of priority, *u*<sup>2</sup> ≀*<sup>v</sup>*2, we repeat the argument we used for *<sup>u</sup>*<sup>1</sup> ≀*<sup>v</sup>*1. More precisely, *u*<sup>2</sup> ≀*<sup>v</sup>*<sup>2</sup> could potentially be applied, one or more times, to the substring *<sup>w</sup>k*−1<sup>π</sup>(<sup>ψ</sup>1), when tokenizing <sup>π</sup>(*<sup>w</sup>*<sup>1</sup> ≀ ... ≀*<sup>w</sup>k*−<sup>1</sup> ≀<sup>ψ</sup>1), but *<sup>u</sup>*<sup>2</sup> ≀*<sup>v</sup>*<sup>2</sup> is not applied across any of the (*<sup>k</sup>* − <sup>2</sup>) tokenization boundaries in *w*<sup>1</sup> ≀ ... ≀*<sup>w</sup>k*−1, otherwise it would have when <sup>π</sup>(<sup>φ</sup> ≀τ) was tokenized using *<sup>D</sup>*. Thus, <sup>T</sup> *D*<sup>2</sup> hf (*w*) is a refinement of a tokenization of the form *w*<sup>1</sup> ≀ ... ≀*<sup>w</sup>k*−<sup>2</sup> ≀<sup>ψ</sup>2.

We iterate this procedure for *<sup>i</sup>* = <sup>3</sup>,...,*<sup>n</sup>* to obtain the theorem.

*Example* <sup>4</sup>*.* In this example, we consider the bound ∣τ∣ ≥ ∣*D*∣, in the previous corollary. Fix a positive integer *n* and let *D* be a dictionary with the following *n* rules:

$$a_1 {}^2 a_{n+1}, a_{n-1} {}^2 a_n a_{n+1}, a_{n-2} {}^2 a_{n-1} a_n a_{n+1}, \dots, a_1 {}^2 a_2 \dots a_{n+1}$$

Also, let <sup>φ</sup> = *<sup>a</sup>*0, <sup>τ</sup> = *<sup>a</sup>*<sup>1</sup> ≀*a*2 ≀ ... ≀*<sup>a</sup>n*, and let <sup>ψ</sup> = *<sup>a</sup>n*+1. Then, <sup>T</sup> *<sup>D</sup>*(π(<sup>φ</sup> ≀τ)π(ψ)) = *<sup>a</sup>*<sup>0</sup> ≀*<sup>a</sup>*1*a*<sup>2</sup> ...*an*+1, and we can not move any prefix of the tokenization of τ to φ, otherwise we no longer have T *<sup>D</sup>*(π(<sup>φ</sup> ≀τ)π(ψ)) = <sup>φ</sup> ≀<sup>ψ</sup> ′ , for some tokenization ψ ′ . ◇

Theorem [2](#page-8-0) may at first appear quite abstract, but they demonstrate a fact that is very useful in practice: a finite lookahead is sufficient to tokenize a string from left to right.

Definition 7. The *sufficient lookahead* of a proper dictionary *<sup>D</sup>* is ∣*D*∣ ⋅max{∣*uv*∣ ∣ *<sup>u</sup>*≀*<sup>v</sup>* ∈ *<sup>D</sup>*}. Observe that by Theorem [2](#page-8-0) the sufficient lookahead is greater than or equal to *<sup>l</sup>*(*D*).

That is, for a proper dictionary *D* and a string *w*, if we know that φ is a prefix of T *<sup>D</sup>*(*w*) (beginning the process by taking ∣φ∣ = 0) we can compute a prefix <sup>φ</sup> ≀*<sup>u</sup>* by inspecting only the sufficient lookahead many next symbols. Observe that this lookahead length does not depend on ∣*w*∣. This has potential to improve tokenization performance by cache locality (where e.g. SentencePiece [\[4\]](#page-11-4) and HuggingFace [\[2\]](#page-11-7) access the string contents with random access), but also enables doing streaming tokenization using a constant amount of memory, for when the entire string is not available or impractical to hold in memory. One way to express this finite state tokenization approach is as a deterministic string-to-string transducer. First, to avoid special cases for the end of the string, let us define a simple normal form.

Definition 8. For a dictionary *<sup>D</sup>* over the alphabet <sup>Σ</sup>, let *<sup>k</sup>* be the sufficient lookahead for *<sup>D</sup>*, assume *<sup>z</sup>* ∉ <sup>Σ</sup>, then a string *<sup>v</sup>* ∈ (Σ∪{*z*})<sup>∗</sup> is the *end-padding of w* if it is of the form *wzz*⋯*<sup>z</sup>* where there are a total of *<sup>k</sup>* trailing *z*s.

*Remark* 4*.* Observe that if *v* is *w* end-padded, then we have T *<sup>D</sup>*(*v*) = <sup>T</sup> *<sup>D</sup>*(*w*)≀<sup>φ</sup> where <sup>φ</sup> = *<sup>z</sup>*≀⋯≀*z*, since *<sup>D</sup>* contains no rules involving *z*. This means that tokenizing *v* from the left to right we can end the procedure the moment the lookahead consists only of *z*s, as that is the padding which will always tokenize to <sup>φ</sup> = *<sup>z</sup>*≀⋯≀*z*. ◇

This allows us to state a straightforward left-to-right tokenization algorithm without having special cases for when the

<span id="page-9-0"></span>Algorithm 2. Let *D* be a proper dictionary over the alphabet Σ and *k* its sufficient lookahead. Assume that *<sup>z</sup>* ∉ <sup>Σ</sup>.

Precompute *<sup>f</sup>* ∶ (Σ∪{*z*})*<sup>k</sup>* → <sup>Σ</sup> ≀ such that for all *<sup>w</sup>* ∈ <sup>Σ</sup>∪{*z*} we have *<sup>f</sup>* (*w*) = *<sup>u</sup>* where <sup>T</sup> *<sup>D</sup>*(*w*) = *<sup>u</sup>*≀<sup>τ</sup> for some τ. Observe that then T *<sup>D</sup>*(*ww*′ ) = *<sup>u</sup>*≀<sup>τ</sup> ′ for all *w* ′ as well, by Theorem [2.](#page-8-0)

Then for any string *w* let *v* be its end-padding, we can then compute T *<sup>D</sup>*(*v*) using the following steps.

- 1. Split *<sup>v</sup>* = *<sup>v</sup>* ′ *v* ′′ such that ∣*<sup>v</sup>* ′ ∣ = *<sup>k</sup>*.
- 2. If *v* ′ = *<sup>z</sup>*⋯*z*, halt.
- 3. Lookup *<sup>f</sup>* (*<sup>v</sup>* ′ ) = *<sup>u</sup>*, output *<sup>u</sup>*.
- 4. Split *<sup>v</sup>* = *uu*′ (observe that *u* must be a prefix of *v* ′ and in turn *v*).
- 5. Update *v* to be *u* ′ , then go to 1.

Theorem 3. *For any fixed proper D and any string w, Algorithm [2](#page-9-0) outputs* T *<sup>D</sup>*(*w*) *in time* O(∣*w*∣) *and using* O(1) *taking D to be fixed and the input string to be read only.*

*Proof.* Correctness follows from Theorem [2,](#page-8-0) with the algorithm picking tokens based on a long enough prefix of the string (guaranteed to exceed *<sup>l</sup>*(*D*)) that it is guaranteed that any suffixes will still have the correct tokenization produce that same token.

The time and space bounds are trivial noting that each iteration step uses up part of the string, and suitably implemented each step uses an amount of time and space bounded in *<sup>l</sup>*(*D*), which is O(1). Reusing space, the indicated bounds are reached.

A perhaps more natural presentation of this algorithm would be constructing a string-to-string transducer. This is not very complicated, the transducer would read *<sup>l</sup>*(*D*) symbols and then, in much the same way as the precomputed *f* in Algorithm [2,](#page-9-0) output a token accordingly. However, the bound here provided is quite large, and a more sophisticated construction is likely needed.

The bound established by Theorem [2](#page-8-0) is clearly quite loose for most realistic dictionaries. Basically, it assumes that the rules in the dictionary create a chain, where each successive rule can "interfere" with the application of the next lower priority rule.

<span id="page-10-0"></span>*Remark* <sup>5</sup>*.* We have from Theorem [2](#page-8-0) that *<sup>l</sup>*(*D*) ≤ ∣*D*∣ ⋅max{∣*uv*∣ ∣ *<sup>u</sup>*≀*<sup>v</sup>* ∈ *<sup>D</sup>*}, where *<sup>l</sup>*(*D*) is the lookahead constant of *<sup>D</sup>*, since ∣π(τ)∣ ≥ ∣*D*∣⋅max{∣*uv*∣ ∣ *<sup>u</sup>*≀*<sup>v</sup>* ∈ *<sup>D</sup>*}, implies∣τ∣ ≥ ∣*D*∣. Next, we consider (informally) how to improve the bound ∣τ∣ ≥ ∣*D*∣, which will then improve the bound on the lookahead constant. Consider dictionaries *<sup>D</sup>* = [*a*≀*b*,*c*≀*d*,*ab*≀*cd*] and *<sup>D</sup>* ′ = [*c*≀*d*,*a*≀*b*,*ab*≀*cd*], i.e. *<sup>D</sup>* and *<sup>D</sup>* ′ have the same rules, but we switched the order of the first two rules in these dictionaries. Now, note that the tokenizations of any string *w* will be the same, independent of if we use *D* or *D* ′ . We say that dictionaries *D* and *D* ′ are *equivalent* if T *<sup>D</sup>*(*w*) = <sup>T</sup> *D* ′ (*w*) for all strings *<sup>w</sup>* ∈ <sup>Σ</sup> ∗ . The complexity of deciding if two dictionaries are equivalent, and if equivalence is even decidable, is left for future research.

Next, we define the *chain length* of a dictionary *<sup>D</sup>*, denoted as *<sup>c</sup>*(*D*). For a dictionary *<sup>D</sup>*, we let *<sup>c</sup>*(*D*) be the maximum value of *<sup>n</sup>* such that we have a sequence of rules of decreasing priority, *<sup>r</sup>*1,...,*rn*, in all dictionaries equivalent to *<sup>D</sup>*. Thus, we certainly have that *<sup>c</sup>*(*D*) ≤ ∣*D*∣. Again, the complexity of computing *<sup>c</sup>*(*D*) will be considered in a future publication, but once we have some, but necessary all dictionaries equivalent to *<sup>D</sup>*, we can obtain an upper bound for *<sup>c</sup>*(*D*), most likely better than ∣*D*∣. In particular, if *<sup>r</sup>* = *<sup>u</sup>*≀*<sup>v</sup>* and *<sup>r</sup>* ′ = *<sup>u</sup>* ′ ≀*v* ′ are neighbouring rules in *D*, such that a non-empty suffix of *uv* is not a prefix of *u* ′ *v* ′ , a non-empty prefix of *uv* is not a suffix of *u* ′ *v* ′ , and *uv* is not a substring of *u* ′ *v* ′ , and we have similar conditions when swapping *r* and *r* ′ , then certainly we can switch *r* and *r* ′ in *D* and this will not change the tokenization of any string. For example, if *<sup>D</sup>* = [*a*≀*b*,*c*≀*d*,*ab*≀*cd*], then *<sup>c</sup>*(*D*) ≤ 2, since [*a*≀*b*,*c*≀*d*,*ab*≀*cd*] and [*c*≀*d*,*a*≀*b*,*ab*≀*cd*] are equivalent dictionaries.

Finally, note that with these concepts in hand, the proof of Theorem [2](#page-8-0) actually shows a stronger result: the theorem holds if we replace the bound ∣τ∣ ≤ ∣*D*∣ by ∣τ∣ ≤ *<sup>c</sup>*(*D*). This can be seen by noting that the proof of Theorem [2](#page-8-0) implies that there is a sequence of rules *r*1,...,*rn*, such that if we apply these rules in order, as in HuggingFace semantics, then we obtain a refinement of *w*<sup>1</sup> ≀ ... ≀*<sup>w</sup>k*−*<sup>i</sup>* ≀<sup>ψ</sup>*<sup>i</sup>* after having applied *r<sup>i</sup>* . But, independently of which dictionary equivalent to *D* is used, *r*<sup>1</sup> is only potentially applied over the tokenization boundary between *<sup>w</sup><sup>k</sup>* and <sup>ψ</sup>, and not over any of the (*n*−1) tokenization boundaries between any of the *w<sup>i</sup>* . Similarly, none of the *r<sup>i</sup>* , with *<sup>i</sup>* ≥ 2, is applied over any of the (*k*−*i*−1) tokenization boundaries in *w*<sup>1</sup> ≀ ... ≀*<sup>w</sup>k*−*<sup>i</sup>* . This is the case, since with equivalent dictionaries, by definition, we obtain the same tokenization, and as shown in the proof of Theorem [2,](#page-8-0) in order to cross the next tokenization boundary from the right, we need a lower priority rule. In summary, each *r<sup>i</sup>* from *r*<sup>1</sup> ...*rn*, will, in order, cross at most one more tokenization boundary, from the right, in *w*<sup>1</sup> ≀ ... ≀*<sup>w</sup><sup>k</sup>* ≀ψ*i* , and each *r<sup>i</sup>* has lower priority than *ri*−1, independent of which dictionary equivalent to *D* is considered. We thus have that *<sup>l</sup>*(*D*) ≤ *<sup>c</sup>*(*D*) ⋅max{∣*uv*∣ ∣ *<sup>u</sup>*≀*<sup>v</sup>* ∈ *<sup>D</sup>*}.

It is necessary to obtain *<sup>c</sup>*(*D*) through a more efficient procedure than pure enumeration. Note, the enumeration involved in constructing *<sup>f</sup>* in Algorithm [2](#page-9-0) inefficiently "finds" the true *<sup>l</sup>*(*D*) anyway. ◇

## 5 Conclusions and Future Work

In some ways, the main contribution of this paper is the more formal definition of the tokenization semantics, allowing them to be studied in closer details. We leveraged this to establish some interesting properties of tokenizations, and established algorithms for both incrementally modifying a tokenization and for doing tokenizations left-to-right using space constant in the length of the string.

Much future work remains, including the following.

- Experimental studies should be performed, for example, testing how the incremental algorithm behaves in random cases. It seems likely to be extremely efficient in practice, as long chains of changes, or infinite ones such as in Example [2,](#page-3-2) do not seem to be very common or realistic. We do

<span id="page-11-0"></span>not offer implementation details in this paper, as in *general* the bounds implied by the constructions are high enough to be impractical.

- Determining better upper bounds for the lookahead constant. Some more aspects that will be considered, are listed throughout the paper, and in particular in Remark [5.](#page-10-0) Once such bounds are established practical implementation details can be considered.
- Beyond improving the bounds of Theorem [2](#page-8-0) there is also its converse, determining how much a tokenization may change from appending strings on the *left.* Example [2](#page-3-2) already demonstrates that this is not finite for all *D*, but from random testing it seems to *often* be finite. It should be investigated whether the dictionaries exhibiting these infinite ripples of changes do so due to some easily decidable property, and whether the "lookbehind" (compare Definition [6\)](#page-7-0) is efficiently computable when finite.
