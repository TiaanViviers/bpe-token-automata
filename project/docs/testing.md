## Notes

Dictionary equivalence and token-level matching live in `tests/test_extensions.py`.
The restricted partial-order checks live in `tests/test_partial_order.py`.
Equivalence uses the independent reference tokenizer and the token-DFA product.
`TokenPatternMatcher.find_canonical` requires the complete input sequence to be
accepted by the supplied token DFA, then checks each reported match span the
same way. A non-canonical segmentation does not come back as a match.

- Pytest collected **161** items in total. Rows above overlap (one function can serve more than one family). The 161 includes §5.4 construction tests, §5.6 harness smokes (`test_timeout_study.py`, `test_hf_merges.py`, `test_realistic_dictionaries.py`), the extension suite, the demo and section-runner checks, and `test_package_smoke.py`. Those extra items are not counted as 6.6. The extension tests contribute **22 tests in total**: **6 dictionary-equivalence checks**, **6 pattern-matching checks**, and **10 restricted-partial-order checks**.
- Uniqueness means: among compositions of the **underlying byte string** \(w\), the token DFA accepts exactly \(T^D(w)\).
- A useful merge (`a⫽a`) changes which token sequences are accepted; the last rule of `proper_with_useless_rule.yaml` (`ab⫽cd`) does not change \(T^D(w)\) on `{a,b,c,d}^{≤6}`.
- Hypothesis failures (spec §6.4 reproducibility): seed `0` is compiled into the test. A failing example is logged to `tests/hypothesis_failures/latest.json` with dictionary, seed, input, and the smallest known counterexample. See [`tests/hypothesis_failures/README.md`](../tests/hypothesis_failures/README.md).
